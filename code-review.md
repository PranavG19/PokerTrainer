# Review: feat/pro-licensing
Verdict: BLOCK
Base: a7d64200ba36589c680f81f9caa3813fd8805829  Head: 2de00fd3446cf61cc0873bc32d9779c689021fdc

## Act on
- src/core/entitlements/clock.ts:49 with src/main/licence.ts:163. An expired licence comes back after a clock rollback if you remove the key and paste it again. `remove()` sets `token = null`, so the next `install()` passes `previousIat === null`, and `highWaterAfterInstall` resets the mark to `max(rolled-back now, iat)`. Probe (tests/tmp/probe-client.test.ts): install, move the clock past exp + grace (expired), set the clock back, Remove, re-paste the same key, and the result is `active pro`. This beats the stated guarantee ("re-pasting an old key cannot") with two clicks and no file edits. Fix: persist the highest `iat` ever installed (`maxIat`, next to `highWater` in the profile and the mirror, kept by `remove()`), and only let a token with `iat > maxIat` reset the mark. Add the remove/re-paste case to licenceAuthority.test.
- src/main/licence.ts:136 (also :95 and src/main/store.ts loadLicenceMirror). An out-of-range stored mark resets the guard. `adopt` takes `Math.max(highWater, stored.highWater)` before `sane()`, and `advanceHighWater` then maps anything over 2200 to 0, so the mark becomes the system clock. Probe: after expiry, set the clock back and put `highWater: 1e20` in the profile ONLY (the settings mirror still holds the true mark). The state goes back to `active`, and the reset mark is written over the mirror too. Fix: clamp each stored value before combining (`Math.max(highWater, saneMark(stored.highWater))`, where an insane value is ignored rather than zeroing the mark). Do the same for the mirror. Add a test.
- src/main/main.ts licence:deeplinkConfirm (the `pendingDeepLink` read). Confirm installs whatever link is pending at that moment, not the one the learner was shown. Probe (tests/tmp/probe-deeplink.spec.ts, real app): link A (annual, ending aaaaaa) is previewed, link B arrives, and `confirm(true)` installs B (`expired`, ending zzzzzz). Fix: `deeplinkPreview` returns an id (a hash of the token). `deeplinkConfirm(accept, id)` installs only if the id matches the pending token. A new link invalidates the old id.
- src/main/licence.ts:150-160 (install). Any verified token replaces the current one, even if it has already expired or grants less. Any web page can open `offsuit://activate?key=<attacker's expired key>`, and one "Add key" click drops a paying user to Free with their own key deleted from disk. Probe: after accepting, state is `expired`, ending zzzzzz. The dialog shows only "Monthly Pro, paid through Aug 13, 2026": no "this has ended" and no "replaces your key ending aaaaaa". Fix: refuse (or require an explicit "replace" step) when the candidate is past its grace, or grants less or has a lower iat than the current valid token, and keep the current token. Preview should say "already ended" and name the key it replaces.
- src/renderer/components/upgradeSheet.ts:115-116,159 and src/main/main.ts licence:openCheckout. The sheet says "checkout stays closed until the first one ships", and docs/PAYMENTS-SETUP.md §4 says checkout stays closed "because CHECKOUT_URLS is empty or the features are unavailable". The code gates checkout only on the URL. tests/e2e/pro.spec.ts "checkout opens in the system browser" itself opens checkout while all 4 features say "Coming in an update". After `payments-setup.ts --checkout-*`, the app sells a subscription with nothing shipped, and the sheet copy is false. With PRICE_LABELS empty it also opens checkout with no price shown, against the decision "the price before checkout". Fix: in main, compute `status.checkout[plan]` and allow openCheckout only when `PRO_FEATURES.some(f => FEATURE_INFO[f].available)` and `PRICE_LABELS[plan] !== ''`. Add a spec that a configured URL with nothing shipped stays closed.
- src/server/licensing/handler.ts:117-161 (apply). The read-modify-write is not atomic, and Stripe sends checkout.session.completed, customer.subscription.created and invoice.paid within milliseconds. Probe (tests/tmp/probe-race.test.ts, MemoryLicenceStore with 5 ms latency): all three at once give `issued, issued, current`, two different lids, two `onIssued` (two emails). The stored record keeps one lid and loses `cs_1` from `orderIds`. The other token's lid returns 404 on refresh, so that buyer never gets a renewal. The same race lets a concurrent grant overwrite a `revoked` put. Fix: serialize per subscription id (a store-level lock, or a compare-and-set/insert-if-absent `put` in the `LicenceStore` contract). Add a latency test.
- src/server/licensing/handler.ts:95-97,111-114. A refund processed before any record exists is lost. `setStatus` does nothing when `existing === null`, and a later grant event then mints. Probe: charge.refunded then customer.subscription.updated gives `revoked`, then `issued`, status `active`. Delivery order is not guaranteed, and a failed or retried grant makes this ordering real. Fix: when no record exists, write a revoked tombstone keyed by subscription id, and have `apply` check it.
- src/server/licensing/stripe.ts:75 and handler.ts:95. Stripe sends `charge.refunded` for partial refunds too, so a goodwill partial refund revokes the licence for good while Stripe keeps billing the subscription. Probe: after a partial refund, the next invoice.paid gives `revoked`. A dispute the merchant wins never un-revokes either. Fix: re-read the charge and revoke only when `amount_refunded >= amount`. For disputes, act on `charge.dispute.closed` with status lost. When revoking, flag or cancel the subscription, so a customer is never billed for a dead licence.
- scripts/payments-setup.ts:57,61. Values go into a `String.replace` replacement string, so `$1`, `$10` and `$12` in a price are expanded as capture groups. Probe (`--dir/--config` in /tmp): `--price-monthly '$10 a month'` writes `monthly: '\n  monthly: 0 a month'`, which breaks config.ts. The docs and the script header also show `"$X a month"` in double quotes, which the shell turns into `" a month"`. Fix: use a replacer function (`(m, p1) => \`${p1}'${value}'\``), and single quotes in docs/PAYMENTS-SETUP.md and the script header.

## Consider
- src/core/entitlements/clock.ts:25 (trustedNow). Licence time freezes; it does not tick. Set the clock back once (to anywhere inside the paid period) and keep it there, and a monthly key stays `active` for good. Probe: still active after a simulated year of sessions. DECISIONS says "a rollback never extends a licence", which is false. Fix: while the system clock is behind the mark, advance the mark by monotonic elapsed time (`performance.now()` / uptime deltas between stamps), or correct the decision line to "freezes". Tradeoff: more code and a small risk of ending a licence early after a big NTP correction.
- src/renderer/components/proSettings.ts:102. "Manage or cancel" appears only while a valid key is on this Mac. The sheet promises "Cancel any time in Settings → Offsuit Pro → Manage or cancel", but a subscriber who removed the key, or whose key reads invalid, cannot reach cancel in the app. Show it whenever `status.manage`. Tradeoff: Free users see a cancel link they do not need (it could be labelled "Manage a subscription").
- src/server/licensing/handler.ts:181-184 (restore). A miss on the order id skips the HMAC, a miss on the email does not, so the timing tells an attacker which orders exist despite the single 404. Compute `emailHash` before the lookup. Tradeoff: one HMAC per request, which is negligible.
- src/server/licensing/handler.ts:130. A past-due → active change with the same period mints a new token (`renewed`), so "minted only when the paid period moves forward" is not true. Compare `paidThrough` whatever `existing.status` is, and update only the status. Tradeoff: none found. A new iat also resets client marks, which is harmless.
- tests/unit/licenceAuthority.test.ts and licenceServer.test.ts. No test covers remove-then-reinstall, an out-of-range stored mark, deep-link swap, a downgrade-by-install, concurrent webhooks, refund-before-grant or partial refund. Add each with the fix above. Tradeoff: none.

## Noted
- The rollback guard is two user-writable files. Deleting or zeroing both (or wiping both, then setting the clock back and re-pasting a saved key) always restores an expired key offline. That is inherent to an offline mark; the threat model should say so.
- src/main/network.ts:70,96-100. `licensingArmed` is module-global, so a second concurrent licensingFetch is disarmed by the first one's `finally`. This fails closed (redirects are `error` anyway) and only risks a spurious network error.
- `store:load` returns the whole profile, token included, to the renderer. EntitlementSnapshot's "no token" is about the snapshot only. The key is the learner's own, so this has no grant impact.
- payments-setup writes the private key file before editing config.ts. If the config edit throws, a re-run refuses with "already exists".
- A dispute is treated like a refund. Decided in DECISIONS, kept, apart from the partial-refund and dispute-won cases above.

## Dismissed
- Forging keys: edited claims with a reused signature, `=` padding, a lowercase prefix, and the S+L Ed25519 malleable signature are all refused. Proof: the forgery tests in tests/tmp/probe-client.test.ts pass. The single failure in that file is a bad probe: the payload had no `-` to swap, and base64urlDecode rejects `+` (token.ts:152).
- Duplicate keys and `__proto__` in claims. Proof: the signature covers the raw payload bytes (token.ts:87), so changing the parse needs the private key. parseClaims copies named fields only.
- Kid confusion (`__proto__`, `constructor`, `toString`, unknown). Proof: the keyring is a `Map` (licence.ts:43). All refused in the probe.
- The committed dev key in a packaged build. Proof: `keyring(true)` skips DEV_KEYS (licence.ts:54). The probe install with isPackaged=true is refused. OFFSUIT_DEV_TIER is ignored (entitlements.ts:115). Devtools are off (main.ts webPreferences).
- A doctored saveState. Proof: `stamp` overwrites tier, granted, licence and highWater (licence.ts:128). Probe and pro.spec "FORGED KEY and DOCTORED SAVE" agree.
- Odd IPC types. Proof: the real app returns `malformed` / `declined` / `missing` / `opened:false` for 42, `'true'`, `null` and `'__proto__'` (probe-deeplink.spec).
- openExternal aimed at an arbitrary URL. Proof: only `endpoints` values are opened, and the plan is compared strictly (main.ts openCheckout). pro.spec covers `https://evil.example`.
- Pointing the licensing session elsewhere. Proof: the origin is fixed from config, `redirect: 'error'`, and only the armed origin is allowed (network.ts:73-101). Nothing else uses the partition.
- Webhook replay, a stale timestamp, a re-signed old body. Proof: HMAC v1 with a 300 s window and the event-id ledger (stripe.ts:37, handler.ts:82). Re-signing needs the whsec secret.
- An event for another customer's subscription. Proof: events are Stripe-signed, and grants come from `getSubscription` (handler.ts:99), not the body.
- Restore enumeration by response. Proof: every miss returns the same 404 body (probe). The timing gap is under Consider.
- Egress without a user action. Proof: no-network.spec (the licensing test included) passes. licensingFetch is reached only from the refresh/restore handlers.
- The profile schema recipe. Proof: the new keys sit under `progression.entitlements`, are in PROGRESSION_SHAPE, and are carried by profileSchema's unknown-key carry. The mirror covers older builds. An additive change needs no bump.
